# Архитектура Telegraph Publisher

## Обзор

**Telegraph Publisher** — CLI-инструмент на Bun/TypeScript для публикации Markdown в Telegra.ph. Поддерживает EPUB, GitHub Gist, PDF/SVG, управление зависимостями, кэширование и валидацию ссылок.

## Стек

- **Runtime:** Bun
- **Язык:** TypeScript (ESNext, strict)
- **CLI:** Commander.js
- **Markdown:** marked v17
- **PDF/SVG:** Puppeteer-core
- **Тесты:** Bun test + Vitest coverage
- **Линтер:** Biome

## Слои архитектуры

### 1. CLI слой (cli.ts + cli/)

Точка входа. Использует `commander` для парсинга аргументов. Регистрирует команды через `EnhancedCommands`:

- `pub` — универсальная публикация
- `analyze` — анализ зависимостей
- `config` — управление конфигурацией
- `status` — статус файла
- `reset` — сброс кэша
- `check-links` — проверка ссылок
- `cache-validate` — валидация кэша
- `epub` — генерация EPUB
- `svg` / `pdf` — генерация изображений/PDF
- `gist` — публикация в GitHub Gist

### 2. Workflow слой (workflow/)

`PublicationWorkflowManager` оркестрирует полный цикл публикации:
1. Инициализация и валидация кэшей
2. Сканирование и верификация ссылок
3. Авторемонт битых ссылок
4. Публикация через `EnhancedTelegraphPublisher`
5. Замена локальных ссылок на Telegraph URL

### 3. Publisher слой (publisher/)

`EnhancedTelegraphPublisher` — расширение базового `TelegraphPublisher`:
- Управление метаданными (YAML front-matter)
- Публикация с зависимостями
- Hash-based оптимизация (пропуск неизменённых файлов)
- Rate limiting с интеллектуальной очередью
- Auto-registration страниц
- Поддержка force-republish

### 4. Конвертация (markdownConverter.ts)

Прямая конвертация Markdown в Telegraph Node (без промежуточного HTML):
- Заголовки h1-h6 → header теги
- Списки ul/ol → списки Telegraph
- Таблицы → вложенные списки
- Код с подсветкой синтаксиса
- ToC (table of contents)
- Якорные ссылки
- Цитаты, ссылки, изображения

### 5. Инфраструктурный слой

- **cache/**: AnchorCacheManager + PagesCacheManager (JSON-файлы)
- **links/**: LinkScanner, LinkVerifier, AutoRepairer, LinkResolver
- **dependencies/**: DependencyManager — дерево зависимостей между файлами
- **config/**: HierarchicalConfigCache + IntelligentConfigMerger
- **ratelimiter/**: RateLimiter + CountdownTimer
- **metadata/**: MetadataManager — чтение/запись YAML front-matter

## Поток данных

```
Markdown file
    ↓
ContentProcessor (препроцессинг)
    ↓
MetadataManager (извлечение/добавление front-matter)
    ↓
DependencyManager (построение дерева зависимостей)

# Кэширование

## Компоненты

### PagesCacheManager

Кэш опубликованных страниц. Хранит маппинг: `filename → { path, url, hash, timestamp }`.

- **Файл:** `.telegraph-pages-cache.json`
- **Структура:** `{ [filename: string]: CachedPageInfo }`
- **Методы:** `cachePage`, `getCachedPage`, `hasChanged`, `removeCachedPage`, `clearCache`

### AnchorCacheManager

Кэш якорей (заголовков) страниц. Используется для валидации внутренних ссылок.

- **Файл:** `.telegraph-anchors-cache.json`
- **Структура:** `{ [path: string]: { anchors: string[], timestamp: string } }`
- **Методы:** `updateCache`, `getAnchors`, `validateAnchors`, `clearCache`

## Стратегии кэширования

### Hash-based optimization

При публикации вычисляется MD5 хэш содержимого файла (без YAML front-matter):

```typescript
const currentHash = ContentProcessor.calculateContentHash(content);
```

Если хэш совпадает с сохранённым — файл пропускается (skip). Это основной механизм оптимизации.

### Pre-warming Cache Strategy

- Cache manager инициализируется до начала публикации
- В dry-run режиме кэш всё равно прогревается для консистентности
- Proactive validation: существующие данные из кэша загружаются заранее

### Non-Blocking Cache Operations

- Валидация кэша не блокирует основной поток публикации
- Используется graceful degradation при ошибках кэша

### Force-republish

Флаг `--force-republish`:
1. Пропускает проверку хэша
2. Принудительно обновляет страницу на Telegra.ph
3. Обновляет кэш с новыми данными

## Управление кэшем

- `reset --all` — полный сброс всех кэшей
- `reset --anchors` — сброс кэша якорей
- `reset --pages` — сброс кэша страниц
- `reset --metadata` — сброс метаданных
- `cache-validate` — проверка целостности кэша
- `status` — отображение статуса файла (изменён/не изменён)

# Генерация EPUB

## Обзор

Генерация EPUB реализована через `EpubGenerator` и использует тот же механизм конвертации Markdown, что и публикация в Telegra.ph.

## Компоненты

### EpubGenerator (`src/epub/EpubGenerator.ts`)

- **Вход:** один или несколько Markdown файлов
- **Выход:** EPUB файл (OEBPS формат)
- **Опции:** заголовок, автор, выходной путь

### Процесс

1. Парсинг Markdown через `markdownConverter` (переиспользование)
2. Построение структуры EPUB:
   - OPF манифест
   - NCX навигация (TOC)
   - XHTML контент
3. Добавление метаданных (DC метаданные)
4. Публикация EPUB (сборка .epub архива)

### CLI

```bash
telegraph-publisher epub -f article.md -o output.epub --title "Title" --author "Author"
```

## Особенности

- **Переиспользование conversion engine:** EPUB использует ту же логику конвертации, что и Telegraph публикация
- **Поддержка TOC:** автоматическая генерация оглавления на основе заголовков
- **Метаданные:** DC title, creator, language, date
- **Тестирование:** `EpubGenerator.test.ts` — модульные тесты генерации

## Ограничения

- EPUB 2 (не EPUB 3)
- Базовая поддержка CSS
- Изображения встраиваются как base64

# Конвертация Markdown → Telegraph Node

## Ядро: markdownConverter.ts

`markdownConverter.ts` — сердце проекта (1056 строк). Преобразует Markdown напрямую в Telegraph Node, **без промежуточного HTML**.

## Поддерживаемый синтаксис

| Markdown | Telegraph Node |
|----------|---------------|
| `# h1` – `###### h6` | `<h1>` – `<h6>` |
| `**bold**`, `__bold__` | `<b>` |
| `*italic*`, `_italic_` | `<i>` |
| `[text](url)` | `<a href="url">` |
| `![alt](src)` | `<img src="src">` |
| `- item` / `1. item` | `<ul>` / `<ol>` |
| `` `code` `` | `<code>` |
| `> quote` | `<blockquote>` |
| `` ``` `` блок | `<pre>` |
| `---` | `<hr>` |
| Таблицы | Вложенные списки ( `<ul>` ) |
| Сноски (footnotes) | Поддерживаются |

## Table of Contents (ToC)

- **Aside ToC:** плавающий блок сбоку
- **Inline ToC:** встраивается в текст
- **Якорные ссылки:** `[text](#section-id)`
- **Настройка:** `--toc-title`, `--toc-separators`

## Якоря (AnchorGenerator)

`AnchorGenerator` (`src/utils/AnchorGenerator.ts`) отвечает за:

- Генерацию slug из заголовков (транслитерация кириллицы)
- Дедупликацию якорей
- Кэширование якорей (AnchorCacheManager)
- Обработку вложенных заголовков

## Конвертация таблиц

Так как Telegraph не поддерживает `<table>`, таблицы конвертируются во вложенные списки:

```
Header1 | Header2
--------|--------
Cell1   | Cell2
```

превращается в:

```
<ul>
  <li>Header1
    <ul><li>Header2</li></ul>
  </li>
  <li>Cell1
    <ul><li>Cell2</li></ul>
  </li>
</ul>
```

## Валидация

- **Размер:** проверка лимита 64KB (Telegraph API)
- **HTML теги:** `validateCleanedContent` запрещает HTML
- **Структура:** проверка корректности дерева Node

# Publishing Pipeline

## Общий поток публикации

### 1. Инициализация

`EnhancedCommands.handleUnifiedPublishCommand`:

1. Разрешение путей файлов (один файл, директория или рекурсивный обход)
2. Создание `PublicationWorkflowManager` с конфигурацией и access token
3. Инициализация подсистем (кэш, метаданные, линковщик)

### 2. Pre-processing

`PublicationWorkflowManager.publish`:

1. **Cache pre-warming**: инициализация PagesCacheManager, валидация anchor cache
2. **Сбор файлов**: определение набора файлов для публикации
3. **Проверка хэшей**: вычисление MD5 хэша контента, пропуск неизменённых

### 3. Обработка ссылок

- `LinkScanner.scanFile` — поиск всех ссылок в файле
- `LinkVerifier.verifyLinks` — проверка доступности (HEAD запросы для внешних)
- `AutoRepairer.repairLinks` — авторемонт битых ссылок

### 4. Конвертация

`convertMarkdownToTelegraphNodes`:
- Парсинг Markdown через `marked`
- Построение дерева TelegraphNode
- Генерация ToC, якорных ссылок
- Валидация размера (лимит 64KB)

### 5. Публикация

`EnhancedTelegraphPublisher.publishWithMetadata`:

1. Проверка хэша → пропуск если контент не изменился
2. Создание/обновление страницы через Telegraph API
3. Rate limiting через `IntelligentRateLimitQueueManager`
4. При превышении лимита — переключение аккаунта (account switching)

### 6. Post-processing

- `LinkResolver.replaceLinks` — замена локальных ссылок на Telegraph URL
- `MetadataManager.addMetadata` — обновление YAML front-matter с URL
- `PagesCacheManager.cachePage` — сохранение результата в кэш
- `AnchorCacheManager.updateCache` — обновление кэша якорей

## Работа с зависимостями

`DependencyManager.buildDependencyTree`:

- Построение графа зависимостей между .md файлами
- Определение порядка публикации (сначала зависимости)
- Фильтрация по глубине (max_depth)
- Публикация зависимостей перед основным файлом

## Форматы вывода

### Telegra.ph
- Прямая публикация через Telegraph API
- Поддержка create/edit страниц
- Автоматическая замена ссылок

### EPUB
- Генерация через `EpubGenerator`
- Использует тот же механизм конвертации Markdown
- Поддержка TOC, метаданных, обложки

### GitHub Gist
- Публикация через GitHub API
- Создание приватных/публичных gist
- Один файл за раз

### SVG/PDF
- Рендеринг через Puppeteer (headless Chromium)
- SVG — векторная графика
- PDF — через печать SVG в Puppeteer

### 📚 Генерация EPUB
Команда для создания электронных книг в формате EPUB из Markdown файлов. Полностью переиспользует механизм публикации Telegraph, включая обработку контента, метаданных и зависимостей.

```bash
telegraph-publisher epub [опции]
```

**Основные опции:**
- `-f, --file <path...>` - Путь(и) к Markdown файлу(ам) (обязательно, можно указать несколько файлов)
- `-o, --output <path>` - Путь к выходному EPUB файлу (по умолчанию: `book.epub`)
- `-t, --title <title>` - Название книги (автоматически извлекается из первого файла если не указано)
- `-a, --author <name>` - Имя автора (обязательно)
- `--cover <path>` - Путь к файлу обложки (cover.jpg или cover.png)
- `--debug` - Режим отладки (сохранить временные файлы для анализа)
- `--language <lang>` - Код языка книги (по умолчанию: `ru`)

**Управление зависимостями:**
- `--with-dependencies` - Автоматически включать связанные локальные файлы (по умолчанию: true)
- `--no-with-dependencies` - Пропустить автоматическое включение зависимостей

**Table of Contents:**
- `--toc-title <title>` - Заголовок для оглавления (по умолчанию: `Содержание`)
- `--toc-separators` - Добавить горизонтальные разделители вокруг оглавления (по умолчанию: true)
- `--no-toc-separators` - Отключить разделители вокруг оглавления

**Примеры использования:**

```bash
# Простая генерация EPUB из одного файла
telegraph-publisher epub -f chapter.md -a "Автор" -o book.epub

# Генерация EPUB из нескольких файлов
telegraph-publisher epub -f chapter1.md chapter2.md chapter3.md -a "Автор" -t "Название книги"

# Генерация с обложкой
telegraph-publisher epub -f chapter1.md chapter2.md -a "Автор" --cover cover.jpg -o book.epub

# Генерация с зависимостями (автоматически включит связанные файлы)
telegraph-publisher epub -f main.md -a "Автор" --with-dependencies

# Генерация без зависимостей
telegraph-publisher epub -f main.md -a "Автор" --no-with-dependencies

# Генерация с кастомным языком и заголовком оглавления
telegraph-publisher epub -f chapter.md -a "Author" --language en --toc-title "Table of Contents"

# Генерация в режиме отладки (сохранить временные файлы)
telegraph-publisher epub -f chapter.md -a "Author" --debug -o debug-book.epub
```

**Особенности:**
- ✅ **Переиспользование механизма публикации** - использует тот же конвертер Markdown, обработчик метаданных и систему зависимостей
- ✅ **Отдельные HTML файлы** - каждый Markdown файл становится отдельной главой в EPUB (поддерживается всеми читалками)
- ✅ **Поддержка обложки** - возможность добавить файл обложки (JPG/PNG) для профессионального вида книги
- ✅ **Режим отладки** - опция `--debug` сохраняет временные файлы для анализа структуры EPUB и HTML
- ✅ **Автоматическая обработка** - метаданные, ссылки и форматирование обрабатываются автоматически
- ✅ **Валидный EPUB 3.0** - соответствует стандарту EPUB для совместимости со всеми читалками
- ✅ **Без внешних зависимостей** - использует только встроенные возможности Node.js/Bun для создания ZIP архива

### 🐙 Публикация в GitHub Gist
Команда публикует один markdown-файл в gist. Контент собирается тем же способом, что и в `pdf` (объединение зависимостей + переписывание локальных ссылок на якоря).

```bash
telegraph-publisher gist [опции]
```

**Основные опции:**
- `-f, --file <path...>` - Путь(и) к входным Markdown-файлам (обязательно)
- `--token <token>` - GitHub token (или сохраните через `config --github-token`)
- `--with-dependencies` - Включать локальные markdown-зависимости (по умолчанию: true)
- `--no-with-dependencies` - Не включать зависимости
- `--filename <name>` - Имя файла внутри gist (по умолчанию: `*_pdf.md`)
- `--description <text>` - Описание gist
- `--public` - Сделать gist публичным (по умолчанию gist приватный)
- `--save-merged` - Сохранить merged markdown локально перед публикацией

**Поведение:**
- При первом запуске создается gist и выводится ссылка.
- При следующих запусках команда обновляет тот же gist (ID хранится в front-matter исходного файла).
- В gist всегда отправляется один markdown-файл.

#### Как получить `GITHUB_TOKEN`

Рекомендуемый вариант: **Fine-grained Personal Access Token**.

1. Откройте GitHub: `Settings` → `Developer settings` → `Personal access tokens` → `Fine-grained tokens`.
2. Нажмите `Generate new token`.
3. В `Resource owner` выберите свой пользовательский аккаунт.
4. В разделе `Permissions` задайте:
   - `Account permissions` → `Gists` → `Read and write`.
5. Сгенерируйте токен и сразу сохраните его в безопасном месте (GitHub показывает его один раз).

Альтернатива: **Personal access token (classic)** с scope `gist`.

Важно:
- Для API создания/обновления gist fine-grained токену нужен permission `Gists (write)`.
- Если у вас organization-политики на токены, доступ может требовать approval администратора.

2. Через переменную окружения:

# или

```

3. Через флаг команды:
```bash

```

### 🔐 Автоматическая регистрация

#### Что такое автоматическая регистрация?
Telegraph Publisher автоматически создает аккаунт Telegraph, если у вас нет токена доступа. Это позволяет начать публикацию без предварительной настройки.

#### Как это работает:
1. **При первом запуске** без токена система автоматически создаст новый аккаунт Telegraph
2. **Токен сохраняется** в конфигурационном файле для последующего использования
3. **Уникальные имена** генерируются автоматически для избежания конфликтов

#### Преимущества:
- ✅ **Быстрый старт** - не нужно предварительно получать токен
- ✅ **Автоматическая настройка** - все происходит в фоне
- ✅ **Безопасное хранение** - токен сохраняется локально
- ✅ **Умная генерация** - уникальные имена для каждого пользователя

#### Управление автоматической регистрацией:
```bash
# Включена по умолчанию - просто начните публиковать
telegraph-publisher pub -f article.md

# Отключить автоматическую регистрацию
telegraph-publisher pub -f article.md --no-auto-register

# Использовать собственный токен (авторегистрация отключится)
telegraph-publisher pub -f article.md --token YOUR_TOKEN
```

#### Пример автоматической регистрации:
```
🔐 Токен не найден. Создаю новый аккаунт Telegraph...
📝 Регистрация аккаунта: TelegraphPublisher_1703123456_abc123 (Digital Writer)
✅ Аккаунт успешно создан! Токен: bbbcccddd...
💾 Токен сохранен в конфигурации

```typescript
import { readFileSync, writeFileSync } from 'fs';
import { resolve } from 'path';

/**
 * Removes specific formatting from a Markdown file:
 * - Markdown styling (bold, italic, strikethrough, links, images, headings, lists, blockquotes, code blocks)
 * - Replaces multiple newlines with a single newline.
 * - Removes leading/trailing whitespace from each line.
 * Overwrites the original file.
 * @param filePath The path to the Markdown file.
 */
export function cleanMarkdownFile(filePath: string) {
    try {
        const fullPath = resolve(process.cwd(), filePath);
        let content = readFileSync(fullPath, 'utf8');

        // Remove Markdown styling (bold, italic, strikethrough, links, images, headings, lists, blockquotes, code blocks)
        content = content.replace(/\*\*(.*?)\*\*/g, '$1'); // Bold
        content = content.replace(/__(.*?)__/g, '$1'); // Bold
        content = content.replace(/\*(.*?)\*/g, '$1');  // Italic
        content = content.replace(/_(.*?)_/g, '$1');  // Italic
        content = content.replace(/~~(.*?)~~/g, '$1'); // Strikethrough
        content = content.replace(/\[(.*?)\]\(.*?\)/g, '$1'); // Links
        content = content.replace(/!\[(.*?)\]\(.*?\)/g, '$1'); // Images
        content = content.replace(/^#+\s/gm, ''); // Headings
        content = content.replace(/^[*-]\s/gm, ''); // Lists
        content = content.replace(/^>\s/gm, ''); // Blockquotes
        content = content.replace(/```[\s\S]*?```/g, ''); // Code blocks
        content = content.replace(/`/g, ''); // Inline code

        // Replace multiple newlines with a single newline
        content = content.replace(/\n{2,}/g, '\n');

        // Remove leading/trailing whitespace from each line
        content = content.split('\n').map(line => line.trim()).join('\n');

        writeFileSync(fullPath, content, 'utf8');
        console.log(`Successfully cleaned: ${filePath}`);
    } catch (error: any) {
        if (error.code === 'ENOENT') {
            console.error(`Error: File not found - ${filePath}`);
        } else {
            console.error(`Error processing file ${filePath}: ${error.message}`);
        }
        process.exit(1);
    }
}

    const filePath = process.argv[2];

    if (!filePath) {
        console.error('Usage: bun clean-md <file-path>');
        process.exit(1);
    }

    cleanMarkdownFile(filePath);
}
