## Диагностика списков

Запущен bun --eval с прямым вызовом convertMarkdownToTelegraphNodes для target telegraph и epub. Три случая: compact (1)–3) без пустых строк) -> один p, нет ol/li; spaced (7)–9), отступы и внутренние абзацы) -> только p, нет ol/li; dotted (7. и 8. с продолжением) -> отдельные ol с единственным li-заголовком, продолжения вынесены в p. В src/markdownConverter.ts распознавание orderedMatch и nextOrderedMatch допускает только точку; непустая строка без маркера закрывает listStack независимо от отступа. EPUB использует тот же конвертер, src/epub/EpubGenerator.ts:443. Дополнительно ol не хранит исходное start. Второй пример пользователя содержит строки без отступа (описание мудры, изображение), поэтому граница пункта требует отдельного решения: стандартный разбор не должен молча захватывать внешний текст в предыдущий li. Код и тестовые файлы не изменялись. Это диагностика, не исправление и не QA реализации.
